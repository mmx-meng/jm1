# Windows / Jupyter 运行修复说明

本版保留原包的数据、结果和图件，修复了运行入口与相关脚本的 Windows 兼容问题。

1. 调整问题二、三、四求解脚本的导入顺序：在 `pandas` / `numpy` 之前加载 `ortools`。这是针对当前环境中 `pandas` 先导入时触发的 `WinError 127`；如果单独运行某个求解脚本，也已采用同样顺序。
2. 主入口 `run_revised.py` 及最终 Jupyter notebook 的子进程统一使用 UTF-8，并对关键 JSON 显式指定 UTF-8 读取，避免 Windows 默认 GBK 导致 `UnicodeDecodeError`。
3. 在独立 Python 3.10 环境中按 `requirements_问题二至四_Jupyter.txt` 安装依赖后，已实际跑通 `python run_revised.py`：问题二、问题三、问题四全链路通过，最后报告 `PASS 19 valid PNGs and all Q3/Q4 independent checks`。最终 notebook 的结构校验通过；修订后未重新执行其全部单元，打开后请从第一格重新运行以刷新保存的输出。

使用时先将整个 ZIP 解压到一个目录，在该目录启动 Jupyter 或命令行。确保 Jupyter 内核与安装依赖的 Python 环境一致。可以先运行 `python -m pip install -r requirements_问题二至四_Jupyter.txt`，再运行 `python run_revised.py`。若已有 Anaconda 环境的 OR-Tools 二进制依赖仍损坏，建议新建环境安装依赖；导入顺序修复不能代替修复损坏的 DLL 安装。

原包的预存结果、图件及论述口径未作重新论证或修改。问题四的分组结果仍依赖原包 README 中说明的“增加组内专属中继副本”假设。
